Tutorial Server - CBS

Untuk siapa halaman ini. Anda punya satu komputer baru yang akan dijadikan server, dan ingin memindahkan aplikasi ini ke sana dari komputer development. Semua perintah ditulis lengkap — tinggal salin, ganti bagian yang DITULIS-BEGINI, lalu tempel.
Yang perlu Anda ganti sendiri hanya dua: IP-SERVER dan NAMA-USER.

Gambaran singkat — apa yang sedang kita bangun

Aplikasi ini bukan aplikasi yang dipasang di tiap komputer. Yang dipasang hanya di satu komputer server. Semua PC station cukup membuka halamannya lewat jaringan pabrik.

Cuma 1 server

Database dan status realtime tersimpan di memori satu proses. Jangan pasang aplikasi ini di tiap PC station — tiap PC akan punya database sendiri dan datanya tidak akan pernah menyatu.

Tidak perlu nginx

Backend sekaligus menyajikan halaman webnya. Jadi cukup satu alamat: http://IP-SERVER:5000.

Tidak perlu internet

Setelah terpasang, sistem jalan penuh di jaringan lokal. Internet hanya dibutuhkan sekali saat memasang Node.js & dependency.

Yang perlu disiapkan sebelum mulai

HalKeterangan
Komputer server PC/mini-PC biasa sudah cukup (RAM 4 GB, disk 128 GB). Tidak butuh spesifikasi tinggi — beban 9 line untuk sistem ini ringan. Yang penting: nyala terus dan tidak dipakai orang untuk kerja lain.
Sistem operasi Tutorial ini memakai Ubuntu Server 24.04 LTS — paling cocok karena watchdog & backup otomatis memakai cron. Kalau servernya Windows, lihat catatan di bagian bawah.

Akses Bisa login ke server (langsung di depannya, atau lewat SSH dari komputer Anda) dan punya hak sudo.

Bagian A — File/folder mana yang harus di-copy

Folder project Anda berukuran ±748 MB, tapi yang benar-benar perlu dipindah hanya ±45 MB. Sisanya bukan sekadar pemborosan — ada dua isi yang kalau ikut terbawa justru membuat aplikasi rusak atau salah data.

Anda tidak perlu memilih berkasnya satu per satu. Satu perintah sudah menyiapkan folder berisi tepat apa yang dibutuhkan server. Bagian ini menjelaskan apa isinya dan kenapa — berguna saat suatu hari ada yang perlu diperiksa, tapi tidak wajib dihafal.

Mengirim paketnya ke server — pilih salah satu

Karena release/cbs-server/ sudah berisi tepat apa yang dibutuhkan, tidak ada lagi daftar pengecualian yang perlu diketik. Cukup kirim folder itu apa adanya.

Cara 1 · Lewat jaringan disarankan

Jalankan dari komputer development. Siapkan dulu foldernya di server:

ssh NAMA-USER@IP-SERVER "sudo mkdir -p /opt/cbs && sudo chown \$USER:\$USER /opt/cbs"

Lalu kirim:

rsync -avz --progress \
  /home/alifr/Projects/casuarina-barcode-system/release/cbs-server/ \
  NAMA-USER@IP-SERVER:/opt/cbs/
Perhatikan tanda / di ujung cbs-server/. Garis miring itu berarti "kirim isi folder ini". Tanpa garis miring, isinya akan masuk ke /opt/cbs/cbs-server/ dan semua perintah setelah ini jadi salah alamat.

Cara 2 · Flashdisk / hard disk (kalau server belum terhubung jaringan)

Salin release/cbs-server.tar.gz (±40 MB) ke flashdisk, lalu di server:

sudo mkdir -p /opt/cbs
sudo chown $USER:$USER /opt/cbs
tar -xzf /media/flashdisk/cbs-server.tar.gz -C /tmp
mv /tmp/cbs-server/* /tmp/cbs-server/.[!.]* /opt/cbs/ 2>/dev/null
ls /opt/cbs        # harus terlihat: backend  frontend  package.json  CLAUDE.md

Cara 3 · Git

Kalau nanti project ini sudah Anda push ke GitHub/GitLab privat, cara ini paling rapi untuk update berkala — tapi ingat, git clone membawa seluruh project, bukan paket ramping ini. Saat ini belum ada remote, jadi lewati dulu.

git clone ALAMAT-REPO /opt/cbs
Cek cepat setelah mengirim. Di server, jalankan ls /opt/cbs — harus muncul backend, frontend, dan package.json. Kalau yang muncul justru satu folder bernama cbs-server, berarti garis miring di ujung tadi terlewat; pindahkan isinya naik satu tingkat.

Bagian B — Setelah file sampai di komputer server

Mulai dari sini semua perintah dijalankan di komputer server (langsung di depannya atau lewat SSH). Kita anggap kodenya ada di /opt/cbs.

Baca langkah 4 sebelum menjalankan langkah 5. Ada satu pengaturan yang tertulis permanen ke database saat aplikasi pertama kali dinyalakan, dan setelah itu tidak bisa diubah lewat konfigurasi lagi.

1 Pasang Node.js versi 24

Samakan versi mayor dengan komputer development (v24) agar dependency berperilaku sama.

curl -fsSL https://deb.nodesource.com/setup_24.x | sudo -E bash -
sudo apt-get install -y nodejs

Pastikan berhasil:

node -v        # harus muncul v24.x.x
which node     # harus /usr/bin/node
Jangan pasang Node lewat nvm di server ini. Node dari nvm tersimpan di folder home dan tidak terlihat oleh cron. Akibatnya watchdog & backup otomatis (langkah 9) akan diam-diam tidak pernah jalan — dan Anda baru sadar saat server mati tengah malam dan tidak ada yang menghidupkannya. Pakai cara di atas (NodeSource) supaya Node berada di /usr/bin/node yang selalu terbaca cron.

1b Pastikan jam & zona waktu server benar

Terlihat sepele, tapi ini menentukan kebenaran seluruh data Anda.

Semua jam diambil dari jam komputer server — bukan dari PC station.

Waktu setiap scan, jam buka/tutup rework, dan tanggal shift semuanya dicatat memakai jam server. Ubuntu Server yang baru diinstal biasanya memakai zona waktu UTC, yang 7 jam lebih lambat dari WIB.

Kalau ini terlewat: scan jam 08:00 pagi tercatat sebagai 01:00 dini hari, grafik output bergeser, perhitungan jam istirahat meleset, dan scan sore hari bisa tercatat pada tanggal yang salah. Data yang terlanjur tercatat tidak bisa dibetulkan otomatis — jadi betulkan sebelum shift pertama berjalan.

sudo timedatectl set-timezone Asia/Jakarta
timedatectl

Yang harus terlihat:

Local time: ... WIB
 Time zone: Asia/Jakarta (WIB, +0700)
System clock synchronized: yes
Baris synchronized: yes berarti jam server dikoreksi otomatis lewat internet (NTP). Kalau jaringan pabrik terhubung internet, ini biasanya sudah menyala sendiri — dan itu menguntungkan, karena jam komputer bisa melenceng beberapa menit per bulan bila dibiarkan. Bila tertulis no, nyalakan dengan sudo timedatectl set-ntp true.
Jam PC station juga sebaiknya benar. Data yang tersimpan memakai jam server, tapi hitung mundur & penanda jam istirahat di layar operator memakai jam PC itu sendiri. PC yang jamnya meleset jauh akan menampilkan status istirahat/kerja yang tidak sesuai kenyataan.

2 Pasang PM2

PM2 adalah "penjaga" yang menjalankan backend di latar belakang, menyalakannya lagi kalau mati, dan menghidupkannya otomatis setelah komputer restart.

sudo npm install -g pm2
pm2 -v

3 Pasang dependency & build halaman web

cd /opt/cbs
npm install          # dependency root (concurrently)
npm run setup        # dependency backend + frontend — perlu internet, ±2-5 menit
npm run build        # bikin halaman web siap pakai → frontend/dist
npm run build wajib. Kalau dilewati, backend tetap jalan tapi semua halaman akan kosong / 404, karena file halaman webnya belum dibuat.

4 Tentukan password admin — sebelum dinyalakan

Buka file konfigurasi PM2:

nano /opt/cbs/backend/ecosystem.config.cjs

Cari bagian env: lalu tambahkan dua baris username & password:

      env: {
        NODE_ENV: "production",
        PORT: 5000,
        ADMIN_USERNAME: "adminCbs",
        ADMIN_PASSWORD: "GantiDenganPasswordAnda",
      },

Simpan dengan Ctrl+O → Enter, keluar dengan Ctrl+X.

Kenapa harus sekarang, tidak bisa nanti?

Saat aplikasi pertama kali dinyalakan, database dibuat dan akun admin disalin dari pengaturan ini ke dalam database. Setelah itu, aplikasi hanya membaca akun dari database — pengaturan di file ini tidak pernah dilihat lagi.

Artinya kalau Anda terlanjur menyalakan tanpa mengisinya, password akan terkunci menjadi bawaan (adminCbs / admincbs123!@#), dan mengisi file ini sesudahnya tidak akan mengubah apa pun. Bukan bencana — masih bisa diganti lewat menu Admin → DATA PASSWORD — tapi selama itu sistem produksi berjalan dengan password yang tertulis di dokumentasi.

Catatan teknis: project ini tidak memakai dotenv, jadi file .env tidak pernah dibaca. Satu-satunya tempat mengisi pengaturan adalah blok env di ecosystem.config.cjs ini.

6 Buka firewall & kunci IP server

Buka port 5000 supaya PC station bisa mengakses. Kalau Anda tahu jangkauan alamat jaringan pabrik, batasi hanya untuk jaringan itu — lebih aman, terutama bila jaringannya juga terhubung internet:

# Sesuaikan 192.168.1.0/24 dengan jaringan pabrik Anda
sudo ufw allow from 192.168.1.0/24 to any port 5000 proto tcp
sudo ufw status

Belum tahu jangkauannya? Jalankan ip addr show — kalau IP server 192.168.1.10/24, maka jangkauannya 192.168.1.0/24. Kalau ragu, boleh pakai bentuk sederhana sudo ufw allow 5000/tcp dulu, lalu perketat belakangan.

Kunci IP server agar alamatnya tidak berubah setelah restart — kalau berubah, semua shortcut di PC station langsung mati. Dua cara, pilih yang paling mudah bagi Anda:

Cara mudah — lewat router

Minta bagian IT membuat DHCP reservation untuk MAC address server. Server tetap "otomatis", tapi router selalu memberi IP yang sama. Tidak perlu ubah apa pun di server.

Lihat MAC address & IP sekarang:

ip addr show
Cara manual — di server

Ubuntu Server memakai netplan:

sudo nano /etc/netplan/50-cloud-init.yaml
sudo netplan apply

Pastikan IP yang Anda pilih di luar jangkauan DHCP router, agar tidak bentrok dengan komputer lain.

Setelah itu, uji dari PC lain di jaringan yang sama — buka browser ke http://IP-SERVER:5000. Halaman beranda harus muncul. Kalau belum bisa, lihat bagian masalah.

6b Pakai nama domain lokal (opsional, tapi sangat disarankan)

Supaya tidak perlu mengetik/mengingat nomor IP, server bisa diberi nama — misalnya cbs — sehingga alamatnya menjadi:

Sebelum

http://192.168.1.10:5000/proses/line.html?n=6

Sesudah

http://cbs.local:5000/proses/line.html?n=6

Keuntungan sebenarnya bukan cuma soal enak dibaca. Kalau suatu saat IP server berubah, puluhan shortcut di PC station tidak perlu disentuh sama sekali — karena yang tertulis di shortcut adalah nama, bukan angka. Yang perlu diperbarui hanya terjemahan nama → IP, dan seberapa repot itu sangat tergantung cara yang Anda pilih di bawah.

Cukup kerjakan bagian A saja. Mengganti IP dengan nama sambil tetap memakai port 5000 adalah bentuk yang paling sederhana sekaligus paling cocok dengan aplikasi ini — koneksi realtime di dalam kode memang menunjuk ke port 5000, jadi semuanya langsung cocok tanpa penyesuaian apa pun. Bagian B (menghilangkan :5000) sifatnya tambahan dan umumnya tidak perlu — alasannya dijelaskan di sana.

Cara 1 · Minta IT menambah catatan DNS disarankan

Tidak ada perintah yang dijalankan di server. Cukup sampaikan permintaan ini ke bagian IT/jaringan:

Mohon dibuatkan DNS A record di jaringan pabrik:

    nama    : cbs        (atau cbs.pabrik.local — mengikuti domain internal yang dipakai)
    alamat  : 192.168.1.10        ← IP server dari langkah 6
    tipe    : A

Setelah dibuat, uji dari PC station mana pun (Command Prompt di Windows):

ping cbs
nslookup cbs
Cara 2 · mDNS — nama cbs.local tanpa melibatkan IT

Server "mengumumkan" namanya sendiri ke jaringan. Jalankan di server:

sudo hostnamectl set-hostname cbs
sudo apt-get install -y avahi-daemon
sudo systemctl enable --now avahi-daemon
sudo ufw allow 5353/udp           # port yang dipakai mDNS

Uji dari PC Windows — perhatikan akhiran .local yang wajib ada:

ping cbs.local
Dua hal yang membuat cara ini gagal. Pertama, akhiran .local wajib ditulis — http://cbs saja tidak akan dikenali. Kedua, sebagian jaringan pabrik memblokir lalu lintas multicast antar-switch/VLAN; kalau ping cbs.local gagal dari PC station padahal berhasil di server, kemungkinan besar itu sebabnya — pakai Cara 1 atau Cara 3.
Cara 3 · File hosts di tiap PC station

Paling pasti berhasil, tapi harus diulang di setiap PC — dan harus diubah lagi di setiap PC kalau IP server berubah.

Di Windows: buka Notepad sebagai Administrator (klik kanan → Run as administrator), lalu buka file:

C:\Windows\System32\drivers\etc\hosts

Tambahkan satu baris di paling bawah (IP, spasi/tab, lalu nama):

192.168.1.10    cbs

Simpan. Kalau Notepad menolak menyimpan, berarti belum dibuka sebagai Administrator.

Di Linux: sudo nano /etc/hosts, tambahkan baris yang sama.

B · Menghilangkan :5000 dari alamat umumnya tidak perlu

Pertimbangkan dulu: apakah ada yang benar-benar mengetik alamat ini?

Operator tidak pernah mengetik alamat — mereka mengklik shortcut di desktop, dan alamat lengkapnya sudah tertanam di situ. Panjang-pendeknya alamat sama sekali tidak mereka rasakan. Yang mengetik manual hanya Anda dan beberapa orang kantor yang membuka Inspection Report — dan bagi mereka cbs.local:5000 sudah jauh lebih baik daripada 192.168.1.10:5000.

Menghilangkan :5000 menambah satu bagian yang bisa rusak (aturan pengalihan port di firewall) demi menghemat enam karakter yang jarang diketik. Kalau ragu, lewati bagian ini.

Kalau tetap ingin dilakukan — misalnya alamatnya akan dicetak/ditempel di dinding — beginilah caranya, dan ini yang harus dihindari:

Jangan mengubah PORT menjadi 80.

Ini cara yang paling terpikirkan, dan justru merusak. Halaman Live Monitoring akan berhenti bergerak dan tombol CALL LEADER mati, padahal halaman tetap terbuka dan scan tetap tercatat — jadi kerusakannya tidak langsung kelihatan dan bisa berjalan berhari-hari sebelum ketahuan.

Sebabnya: koneksi realtime (WebSocket & notifikasi panggilan) di dalam aplikasi menunjuk langsung ke port 5000, bukan mengikuti port halaman yang sedang dibuka. Kalau backend dipindah ke port 80, tidak ada lagi yang mendengarkan di 5000 dan koneksi realtime itu gagal tanpa pesan error yang terlihat operator.

Yang benar: biarkan backend tetap di port 5000, lalu suruh sistem mengalihkan port 80 ke sana. Backend tidak berubah sama sekali, port 5000 tetap mendengarkan, realtime tetap hidup — dan pengguna cukup mengetik http://cbs.

Buka pengaturan firewall:

sudo nano /etc/ufw/before.rules

Tambahkan blok berikut di paling atas file, sebelum baris *filter:

*nat
:PREROUTING ACCEPT [0:0]
-A PREROUTING -p tcp --dport 80 -j REDIRECT --to-port 5000
COMMIT

Simpan, lalu izinkan port 80 dan muat ulang:

sudo ufw allow 80/tcp
sudo ufw reload
sudo ufw status
Port 5000 harus TETAP terbuka. Jangan tergoda menutupnya setelah port 80 jalan — koneksi realtime tetap memakai port 5000 secara langsung. Pastikan sudo ufw status masih menampilkan keduanya: 80 dan 5000.

Uji — dan pastikan realtime-nya ikut hidup

Dari PC station (bukan dari server), buka:

http://cbs.local:5000/                        → halaman beranda harus muncul
http://cbs.local:5000/monitoring/line.html?n=6 → angka harus BERGERAK saat ada scan

Kalau memakai Cara 1 (DNS) tulis http://cbs:5000/...; kalau bagian B dikerjakan, :5000-nya boleh dihilangkan.

Halaman yang terbuka tapi angkanya diam adalah tanda khas port 5000 tidak terjangkau. Membuka beranda saja tidak cukup untuk membuktikan sistem sehat — yang membuktikan adalah angka monitoring yang bergerak.

Terakhir: perbarui shortcut di PC station

Setelah nama domain jalan, ubah shortcut di langkah 10 agar memakai nama, bukan IP:

Contoh di atas memakai Cara 2 (mDNS) — akhiran .local wajib ikut ditulis. Kalau memakai Cara 1 atau 3, cukup http://cbs:5000/.... Kalau bagian B dikerjakan, :5000-nya dihilangkan.

C · Kalau suatu hari IP server berubah

Meski di langkah 6 IP sudah dibuat statis, perubahan IP tetap mungkin terjadi. Yang paling sering:

  • Komputer server diganti — hardware baru berarti MAC address baru, sehingga DHCP reservation di router tidak lagi mengenalinya.
  • Router diganti atau di-reset — daftar reservation-nya ikut hilang.
  • IT menata ulang jaringan — penggantian subnet atau pemisahan VLAN.
  • OS server diinstal ulang dan pengaturan IP statisnya belum dipasang lagi.
  • Kabel pindah port/switch ke segmen jaringan yang berbeda.
Shortcut di PC station tidak pernah perlu diubah dalam kejadian mana pun di atas — isinya nama, bukan angka. Begitu juga alamat yang di-bookmark orang kantor.
Kalau Anda memakaiYang harus dilakukan
Cara 2 · mDNS Tidak ada. Server mengumumkan IP barunya sendiri ke jaringan, dan PC station menerjemahkan ulang nama cbs.local setiap kali menyambung. Sistem pulih sendiri dalam hitungan menit — tanpa ada yang perlu menyentuh satu PC pun.
Cara 1 · DNS router/IT Minta IT memperbarui satu catatan A record ke IP baru. Setelah cache DNS di PC habis (biasanya beberapa menit; bisa dipercepat dengan ipconfig /flushdns), semua PC ikut sendiri.
Cara 3 · File hosts File hosts di setiap PC station harus diedit ulang satu per satu. Inilah kelemahan utama cara ini — dan alasan kenapa ia sebaiknya hanya dipakai sebagai cadangan, bukan cara utama.
Aplikasi ini memang dirancang untuk pulih sendiri. Saat sambungan realtime putus, halaman mencoba menyambung ulang berkala (1 → 15 detik) memakai nama server, bukan IP yang tersimpan. Jadi begitu nama itu menunjuk ke IP baru, sambungan tersambung kembali tanpa halaman perlu di-reload. Selama jeda itu, scan tetap bisa dilakukan dan ditahan di antrean lokal — persis seperti saat server mati biasa.
Tetap pakai IP statis walau memakai mDNS. Keduanya saling melengkapi, bukan saling menggantikan: mDNS menyelamatkan Anda ketika IP terlanjur berubah, sedangkan IP statis mencegahnya berubah sejak awal. Dan kalau suatu saat multicast diblokir di jaringan, IP statis adalah jalan mundur yang masih bisa diandalkan.

9 Pasang watchdog & backup otomatis

PM2 hanya bereaksi kalau proses mati. Watchdog menangani keadaan yang lolos dari PM2 — misalnya proses terlihat hidup tapi sebenarnya macet.

cd /opt/cbs/backend
cp .watchdog.env.example .watchdog.env
DRY_RUN=1 bash scripts/watchdog.sh      # uji dulu, tidak benar-benar merestart

Kalau ujinya wajar, pasang penjadwalannya:

crontab -e

Tambahkan dua baris ini di bagian bawah:

# cek kesehatan backend tiap menit
* * * * * /opt/cbs/backend/scripts/watchdog.sh >> /opt/cbs/backend/logs/watchdog.log 2>&1

# backup database tiap 30 menit
*/30 * * * * cd /opt/cbs/backend && /usr/bin/node scripts/backup-db.js >> logs/backup.log 2>&1
Cek keesokan harinya. Jalankan cat /opt/cbs/backend/logs/watchdog.log dan ls /opt/cbs/backend/data/backups/. Cron yang gagal biasanya gagal diam-diam — Anda tidak akan diberi tahu. Kalau backup-nya kosong, kemungkinan besar Node dipasang lewat nvm (lihat peringatan langkah 1).

  • Scan berurutan FT → FI1 → FI2 → FI3 tercatat semua

  • Packing berjalan dan nomor packing berurutan

Kalau jaringan pabrik terhubung internet (mis. berlangganan Biznet)

Semua langkah di halaman ini tetap berlaku apa adanya — tidak ada yang perlu diubah. PC station menghubungi server lewat jaringan lokal memakai alamat internal (192.168.x.x / cbs.local), tidak lewat internet. Data scan tidak pernah keluar dari pabrik, dan kuota internet tidak terpakai untuk operasi harian.

Adanya internet justru memudahkan: pemasangan Node.js & dependency (langkah 1–3) jadi lancar, dan jam server terkoreksi otomatis (langkah 1b). Yang perlu ditambahkan hanya beberapa kewaspadaan berikut.

1 · Jangan pernah membuka akses dari internet

Jangan melakukan port forwarding port 5000 di router.

Permintaan ini biasanya muncul dengan niat baik — "biar bisa dipantau dari rumah". Tapi aplikasi ini dirancang untuk jaringan tertutup pabrik, bukan untuk internet terbuka:

  • Tidak memakai HTTPS — username & password admin dikirim apa adanya dan bisa dibaca di sepanjang jalur.
  • Password tersimpan apa adanya di database (tidak diacak), sesuai kebutuhan pengelolaan manual lewat menu Admin.
  • Tidak ada pembatasan percobaan login — penebakan password bisa dicoba tanpa henti.
  • Menerima permintaan dari alamat mana pun (pengaturan CORS terbuka, wajar untuk LAN).

Selama tidak di-forward, server Anda tidak terjangkau dari internet meski jaringannya online — router menyembunyikannya secara otomatis. Yang berbahaya adalah membukanya dengan sengaja.

Kalau memang butuh akses dari luar pabrik (mis. manajemen ingin melihat Inspection Report dari kantor pusat), mintalah IT menyiapkan VPN ke jaringan pabrik. Dengan VPN, pengguna seolah berada di dalam jaringan lokal — semua kelemahan di atas tidak terekspos ke internet. Ini satu-satunya cara yang aman tanpa mengubah aplikasi.

2 · Batasi port 5000 hanya untuk jaringan pabrik

Sudah dibahas di langkah 6, tapi jadi lebih penting bila jaringannya online. Bentuk yang disarankan:

sudo ufw allow from 192.168.1.0/24 to any port 5000 proto tcp

Dengan begitu, walau suatu saat ada jalur tak terduga dari luar, port-nya tetap tertutup untuk alamat di luar jaringan pabrik.

3 · Router bawaan ISP sering terbatas

Router yang dipasang penyedia internet umumnya punya menu pengaturan yang dikunci sebagian. Dua akibatnya untuk kita:

KendalaDampak & jalan keluar
Tidak bisa menambah catatan DNS sendiri Cara 1 di langkah 6b tidak bisa dipakai. Gunakan mDNS (cbs.local) — tidak butuh dukungan router sama sekali.
Tidak bisa membuat DHCP reservation Atur IP statis langsung di server (cara manual di langkah 6), dan pilih alamat di luar jangkauan DHCP router agar tidak bentrok.
Router diganti/di-reset teknisi ISP Semua pengaturan router hilang, dan IP server bisa berubah. Inilah alasan kenapa mDNS layak dipakai walau Anda sudah memasang IP statis — lihat langkah 6b bagian C.

4 · Dua gangguan khas jaringan perusahaan

GejalaSebab
PC station terhubung internet dengan lancar, tapi tidak bisa membuka server sama sekali PC berada di jaringan/VLAN yang berbeda dari server (misalnya WiFi tamu), atau WiFi memakai AP isolation yang melarang perangkat saling menghubungi. Internet tetap jalan karena arahnya keluar, bukan antar-perangkat. Minta IT menempatkan PC station dan server pada jaringan yang sama.
PC station tiba-tiba restart di tengah shift Windows Update otomatis. Atur jam aktif (active hours) di PC station agar restart tidak terjadi pada jam produksi.
Internet mati tidak menghentikan produksi. Selama jaringan lokal masih hidup, seluruh sistem tetap berjalan normal — scan, monitoring, dan panggilan Leader tidak melewati internet sama sekali. Yang terhenti hanya koreksi jam otomatis, dan itu tidak terasa dalam hitungan hari.
